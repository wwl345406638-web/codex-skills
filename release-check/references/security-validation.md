# 安全验证与证据要求

在执行核心检查第 6 项时读取。检查目标来自当前授权项目的实际入口、数据、身份模型和部署方式。

## 按项目选择工具

优先使用项目已有工具和配置。先核对工具的适用语言、扫描范围、版本、漏洞库更新时间、网络和运行前提，再选择补充工具。

| 验证层 | 可选工具或方式 | 必须复核的覆盖边界 |
| --- | --- | --- |
| 源码与数据流 | Semgrep、CodeQL、语言原生安全检查、人工数据流分析 | 语言与规则覆盖、排除项、动态路由、源码到危险调用的可达性 |
| 依赖 CVE | OSV-Scanner、Trivy、语言包管理器 audit | 所有锁文件与已解析版本、传递依赖、容器/系统包、数据库新鲜度 |
| 密钥 | Gitleaks、TruffleHog、项目已有扫描器 | 工作区、相关 Git 历史、配置、构建产物和日志中的秘密 |
| 动态检查 | OWASP ZAP、接口测试、浏览器与代理抓包 | 登录态、角色、业务范围、测试数据、扫描请求的副作用 |
| SBOM | CycloneDX、SPDX 生态工具 | 与本次发布版本和实际产物对应，标注开发/运行范围及未知组件 |

结合多层结果形成结论，检索匹配用于定位候选问题。逐项阅读上下文与数据流后确认问题和覆盖范围。

## 从入口覆盖到业务边界

| 检查面 | 验证重点 | 合理的修复复测 |
| --- | --- | --- |
| 认证与会话 | 登录/退出、密码重置、默认账号、令牌验证与过期、会话固定、Cookie 属性 | 匿名、过期和撤销态拒绝访问，合法登录及退出流程通过 |
| 授权与越权 | 接口级角色、对象归属、租户/组织边界、列表/导出/批量接口、前后端权限一致性 | 至少使用不同权限或归属的测试账号覆盖允许和拒绝路径 |
| CSRF 与跨域 | Cookie 鉴权写操作的 CSRF 防护、Origin 检查、SameSite、带凭据 CORS | 验证鉴权模式及浏览器实际行为，检查跨站写入与合法请求 |
| 注入与输出 | SQL/NoSQL、命令/模板注入、XSS、反序列化、路径遍历、SSRF、开放重定向 | 跟踪输入到数据库、进程、HTML、文件与网络，验证编码及参数绑定 |
| 文件和外部资源 | 上传类型/大小/存储/执行权限、下载授权、解压路径、回调签名与重放 | 使用隔离文件和受控地址验证边界，确认正常上传下载可用 |
| 业务完整性 | 重复提交、幂等、状态机、并发、交易/库存/绑定约束、重试后状态 | 用可恢复测试数据验证成功、拒绝、失败中断和重复请求 |
| 可用性与滥用 | 限流、分页上限、超时、正则/解析复杂度、资源释放 | 采用有限请求与受限输入验证边界，额外负载测试依授权范围执行 |
| 配置与供应链 | 调试入口、异常栈、公开秘密、CI/CD 凭据、镜像权限、安装脚本、依赖来源 | 对发布配置与实际构建产物复查，验证升级后的兼容性 |

根据项目增加实际存在的协议、WebSocket、任务队列或设备入口。每个检查面记录适用性和覆盖路径，抽样范围明确写出。

## 受控动态验证

1. 解析配置中的目标，确认本地/隔离服务、关联存储和出站地址均在授权范围。将支付、短信、邮件、设备命令等外部副作用替换为项目支持的沙箱或受控桩。
2. 从正常业务请求建立基线，再改变身份、对象标识或输入边界。优先验证最小影响的可复现路径，记录预期与实际结果。
3. 将请求限制在已授权主机与入口，处理重定向和扫描器自动发现的新目标时重新检查范围。预设停止条件与测试数据恢复方式。
4. 修复后复测同一场景，并回归合法用户路径、历史数据、并发/重试及相关错误处理。清理测试数据并检查服务状态。

生产地址、账号或安全执行条件缺失时，记录受影响的生产验证项和补齐条件，继续源码、依赖、配置与可运行的隔离测试。现有授权覆盖的常规动作直接执行。

## 发现问题后的处理

- 密钥命中先确认类型与来源，输出使用脱敏标识。移除源码/产物中的秘密引用，接入项目现有秘密管理方式，并列出轮换/吊销及历史暴露处理需求。实际轮换按既有授权执行，报告残余有效凭据与外部依赖。
- 依赖漏洞结合实际解析版本、可达代码、运行环境和修复版本确认。优先兼容升级或局部修复，更新锁文件后验证构建与业务。对误报、不可达与暂缓项记录可复核依据及适用条件。
- 对鉴权等逻辑问题保留最小复现和修复后的允许/拒绝结果。截图、请求与日志证据经过脱敏，保留必要定位信息。
- 检查器非零退出时先区分发现问题、配置错误、执行失败及网络/漏洞库失败。修复可恢复的执行问题，记录最终状态。测试或扫描完全未运行时标为未执行，部分运行时明确已覆盖部分。

## 单条发现记录

每条记录包含编号、严重度及依据、受影响版本/入口、触发条件、最小复现、业务影响、修改位置、复测证据和当前状态。未知项列明验证所需条件。原始报告和发布结论保持可追溯关联。

示例场景中，普通账号读取另一个组织的资产详情时返回了数据。先在隔离环境用两个组织的账号和测试资产复现，再将组织约束应用到服务端查询，复测跨组织请求被拒绝、同组织详情与列表/导出仍正常。记录测试账号角色与资产脱敏标识、请求/响应状态及代码位置。
