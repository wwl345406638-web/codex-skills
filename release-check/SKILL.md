# 上线检查

完成已授权项目的发布前检查、修复和回归。每项结论对应代码、许可证原文、运行结果或明确的验证缺口。

## 确定范围并开始

- 读取项目指引、工作区改动、技术栈、依赖清单与锁文件、启动/构建命令、部署入口和已有测试。以当前版本建立基线，记录检查对象与时间。
- 用户要求检查并修复时，直接开展项目范围内的常规读取、局部修改、构建、测试和隔离安全验证。沿用现有工程与工具链，保留业务契约、用户改动和有效测试。
- 使用本地或用户授权的隔离环境及测试数据开展动态验证。生产主动扫描依据已明确的目标和允许动作执行，按实际风险核实账号、限速、时间窗和停止条件。缺失生产信息只阻塞相应验证，继续其余工作。
- 对破坏性操作、生产数据修改、凭据轮换和发布执行，遵循已有授权及工具权限。检查任务本身完成后交付可审阅结果，涉及额外外部动作时再取得所需授权。

## 六项核心检查

### 1. 前端无效代码与资源

结合引用关系、构建产物和正常入口确认未用的源码、组件、样式、图片、字体与依赖，再清理关联导入、配置和锁文件。核对动态导入、约定式路由、插件注册、反射及按环境加载。对证据不足的候选记录原因，保留到调用关系查清。清理后检查正常页面、空态、错误态及关键交互。

修复涉及浏览器存储或持久记录时，验证既有数据迁移、账号隔离与写入失败重试。仅在新位置保存成功后清理已迁移的数据，初始化清理应具备明确的数据失效依据。

### 2. 字体商用许可与替换

盘点实际文件、CSS 字体声明、图标字体、远程字体及生成/复制进入产物的字体，核对名称、版本、来源、权利人和许可证原文。确认本次商业使用、Web 嵌入、再分发与子集化对应条款，保留必要声明。借鉴既有项目时重新核验本次字体与使用方式，已上线记录仅作为来源线索，授权结论以许可证或授权凭证为据。

删除确认未使用的字体。对正在使用且授权无法确认或条件不适用的字体，优先采用许可明确、字符覆盖充分的字体或系统字体栈，更新引用并验证中文、图标、字重、回退、换行和打印。报告每款字体的处置与依据。

### 3. 后端废弃测试与调试入口

从实际路由注册、网关规则、环境开关、中间件和调用方核实用途。确认废弃后清理暴露的测试、调试、演示、种子数据及绕过鉴权入口，同时处理关联权限、文档和配置。按业务用途保留自动化测试、有效回调、健康检查、就绪探针和运维必需接口，并核对访问控制。用部署配置启动验证这些入口的最终可达性。

### 4. 自有代码中文维护注释

清点全部自有函数、方法、组件、类、模块、路由处理器和重要回调，逐项核对中文维护说明。简短代码说明用途，复杂逻辑补充关键输入/输出、边界、副作用、异常与业务原因，更新失实注释。内联小回调可由紧邻的中文说明覆盖，确保维护者能定位对应逻辑。

保持语言文档注释语法、类型标记、生成指令和许可证头有效。第三方、vendor、生成、压缩及构建文件按来源标识并排除人工注释，注释写回自有源文件。报告覆盖目录、抽取方式、已覆盖对象及待处理例外。

### 5. 全部开源依赖许可

覆盖每种语言的直接、传递、运行、开发与构建依赖，以及 vendored 代码、复制片段、前端捆绑内容、容器基础镜像和随包资源。依赖清单与实际安装/锁定版本、最终产物交叉核对，输出可追溯的 SBOM，标明范围和未知项。

结合实际包内 LICENSE、COPYING、NOTICE 与权威上游核验许可证表达式、版权、分发方式及义务。重点复核双许可选择、copyleft、源码提供、修改声明、署名与商用限制。为随发布交付的组件生成或更新 `THIRD-PARTY-NOTICES` 及必要许可证文本。授权未知和兼容性未确认项列为待解决，修复选择与业务用途、分发场景一致。

拟随包分发组件的分发权仍缺少依据，或已确认的许可义务尚未满足时，将对应交付列为发布阻塞，落实替换组件、取得授权或满足许可义务的具体处理路径后复核。

### 6. 深度安全扫描、受控渗透与修复

执行前读取 [安全验证与证据要求](references/security-validation.md)。结合架构与业务入口选择 SAST、依赖 CVE/SCA、密钥检测、配置审查和动态验证。围绕真实数据流人工复核扫描结果，对鉴权、越权和业务逻辑等工具盲区设计有针对性的检查。

在授权范围内复现、修复并复测问题，覆盖异常路径和已有调用方。动态测试使用可恢复数据，发现敏感数据外泄、异常负载或越出目标范围时停止该项并保留脱敏证据。按问题影响、可利用性和发布暴露面确定优先级。

## 发布核对与交付

- 检查生产配置、默认账号、调试开关、公开文档/源映射、CORS、Cookie、TLS、错误响应、敏感日志、权限、监控和告警。按实际部署方式核对运行时版本、容器权限、CI/CD 权限、迁移兼容性和密钥注入。
- 运行现有静态检查、类型检查、测试、构建和关键业务回归，必要时补上能捕获已修漏洞的针对性回归。说明失败与本次修改的关系。
- 核对最终发布产物、版本/校验值、锁文件、配置样例、许可证材料、SBOM、备份与恢复依据、回滚版本及数据库迁移策略。按项目实际条件演练可安全执行的恢复/回滚，记录其余待验证部分。
- 交付中文结果，列出检查范围与版本、已修问题、未解决问题及影响、逐项验证证据、未执行/失败/不适用项与原因、发布阻塞项和后续动作。清理、字体、注释、许可及安全各项均有结果。

证据至少包含目标/文件位置、工具与规则/漏洞库版本、命令或复现步骤、时间、退出状态、结果摘要及脱敏证据位置。手工检查记录方法和覆盖对象。扫描失败、工具不可用或漏洞库过期时记录覆盖缺口，尝试可行的修复或替代后继续，结论限定到已验证范围。

发布结论采用“本次范围通过”“存在发布阻塞项”或“验证不足”，并说明依据。将静态、本地动态、隔离集成、生产验证的实际覆盖分别写明。所有修复完成复测后才归入已修复，剩余风险由拥有相应发布权限的人处理。
