# 参考文档样式与写法

从参考文档提炼可复用的排版和写法，让下一位写作者知道每类段落应当怎样排、怎样写。使用用户的语言，遵循本次要求的范围、载体和交付格式。

## 判断本次交付

- **先提取。** 用户说“先理解，提取完再进行下一步”，交付可独立复用的《样式与编写基准》后停下。有参考文档就可以开始，此时无需索取新项目材料。
- **提取并套写。** 用户已经给出新材料并要求成稿，直接提取、映射、编写、核对。用户只要成稿时，在交付说明中交代影响使用的近似项即可。已有基准就接着用，遇到疑点再回查原件。
- **局部修改。** 按指定范围继承相邻同类段落的样式、层级和编号。原文用于提供写法，新事实来自用户指定的新材料。只有用户明确把同一文件也作为内容来源时，才采用其中与本次任务相关的事实。

## 判断能从参考材料读出什么

| 手上的材料 | 取证方式与边界 |
| --- | --- |
| Word、ODT 或可编辑的在线文档 | 先看实际使用的段落，再查对应的段落样式、字符样式、局部覆盖、继承和主题。按节查看页面设置。能读取 DOCX 内部属性时，可用文档工具核对；具体路径见下方“Word 取证”。在线文档按实际可访问的格式属性记录。 |
| 带文字层的 PDF | 查正文与标题的文字片段、嵌入字体、字号及坐标，结合渲染页确认。子集名称、替代字体、相邻文字的几何距离都按它们能证明的含义记录。PDF 行间距离不能单独证明 Word 的行距规则。 |
| 扫描件、截图或图片 | 根据可见页面识别层级、对齐、相对字号和留白。能辨读的文字可用于提炼写法；OCR 可辅助转录。精确字体、字号、页边距或行距须有其他依据。 |
| 粘贴的纯文字或 Markdown | 保留可见的标题标记、段落组织、编号和措辞。聊天中的显示字体和空行不足以还原原文件的字号、段距和行距。 |

发现缺页、加密、损坏或当前工具只返回文本时，说明实际读到了哪些内容，以及它影响哪一项结论。多份参考先按用户指定的主稿、章节或用途分工；同稿的封面、正文、表格、附录可各有规则。只有同一用途出现相互排斥的做法且会影响交付时才需要用户取舍。

## 提取版式与写法

1. **读懂内容。** 先通读可见内容，确定读者、文档用途、各章回答的问题及章节关系。篇幅很长、只能抽样时，覆盖每种实际使用的标题和代表性正文，注明范围。不要从目录或封面推断全文。
2. **把格式对应到角色。** 区分文档标题、各级标题、正文、条款、列表等实际出现的角色。记录标题字体与分级、正文字体与字号、段前段后与行距；按需要补充中西文字体、字重、对齐与缩进、自动或手工编号、编号续排、分页、纸张和边距、表格及图注。列出真实层级映射，拟成稿的首级标题可能用的是原件“标题 3”。保留原始单位与规则，例如“段前 0.5 行”不能写成“0.5 磅”。同类段落的例外单列并说明位置。
3. **把文风写成动作。** 观察每节先讲什么、后讲什么，标题用词、语气、人称、术语、句型、段落长短和展开粒度。把“正式严谨”落实为可以照做的指令。例如原文反复先给判断条件再写责任人和动作，就提炼这个顺序，并指出出自哪个小节。不要把参考文中的业务对象、数值、承诺或章节数量固定成通用规则。
4. **让结果能直接复用。** 提取任务通常交付参考范围与章节作用、可复制的角色样式表、各类段落的写法与例外。样式表可用“角色／原样式或编号／字体与字号／段落设置／出处”。关键数值和规则附一个短定位，如页码、标题路径、样式名或段落号。按依据标明“原件已核实”“按外观估计”“待补充”或“本次采用”。必要时说明“原件指定字体”和“预览实际使用字体”。小任务可用几行完成。

## 处理不确定项

先交付已经能完成的部分。对不影响任务的缺项做简短标记；会改变结果时，只问能推进决定的最少问题，一次给两三个容易回答的选项。用户可直接回复选项或补充一句。用户要求精确值时，保留该项待核；用户接受近似后，把选定值标作本次设置。没有参考材料时，请用户上传一份文档或粘贴一段代表性文字。

- **只有截图又要还原 Word。** “从这张图能判断标题层级和相对大小，正文字号还读不准。你希望 A 发原 Word 或字体设置截图，还是 B 先按外观近似排版？”
- **两份范本对同一角色有冲突。** “两份参考的章标题分别是黑体 16 磅和宋体 14 磅。新稿章标题用 A 稿、B 稿，还是按你指定的章节分别使用？”
- **原件打不开。** “当前只能读到封面。你可以补一份可打开的导出件，或发一页包含标题和正文的截图，我先提取这一页。” 没有可读内容时如实说明，不虚构已完成的提取。

## 应用到新稿并核对

按新稿的读者、事实来源和用户规定的结构，先把新内容对应到参考文档里的段落角色，再套用写法。保留核定的名称、动作、状态、约束及适用条件；原文中的技术选型、性能指标、报价和权利条款只有在新材料中有依据时才写入。缺少关键事实时留待确认，或先写证据充分的部分。

需要 Word 等可编辑成品时，优先在参考副本中使用命名样式、编号与节设置，保留用户要求的模板元素，清理与新稿无关的示例内容。在成品中复读代表性的标题、正文、列表或表格，核对其有效格式、编号连续性和层级；可以渲染时再检查分页、断行与标题孤行。需要纯文本时，交付文字和必要的排版参数。只说明实际完成的检查，以及影响使用的未核实项。

## Word 取证

有原始 DOCX 和文件分析能力时，从代表段落回查段落属性、字符片段、样式继承、文档默认、主题、编号及分节属性。解读底层数值要看字段和单位。例如字号字段 `sz=32` 为 16 磅；段距字段 `beforeLines=50` 为 0.5 行；`line=276` 配合 `lineRule=auto` 为 1.15 倍行距。具体数值每次从本次原件取证。页眉页脚、表格样式、文本框和字体替代要另查相关内容或渲染页。只能读取文字时，按纯文字范围交付。

在含脚本的技能包中，可用 Python 3 运行 [Word 取证脚本](scripts/inspect_docx.py)。从技能目录执行 `python3 scripts/inspect_docx.py "参考文件.docx"`（文件也可给绝对路径）。它输出正文含表格内的段落位置、样式链、直接格式、编号等原始属性；再读取正文对应位置，才能判断角色和行文。没有脚本的环境，直接使用可读的文件属性执行同一流程。
