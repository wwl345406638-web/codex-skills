# 页面设计与交互精修

在第一版设计就确定用户要看见什么、用什么数据画、操作后如何变化。已有页面从用户指出的区域和问题入手，沿用项目的组件、设计变量、业务字段与操作习惯。

## 从需求到可渲染的页面

1. **确定第一屏。** 写清使用者、设备、第一眼要判断的事和下一步操作。确定视觉中心、阅读顺序和内容密度。先看现有页面、截图、品牌规范及可用素材。
2. **把视觉意图换成参数。** 当需求说“专业”“高级”“有科技感”时，针对目标区域给出能画出来的决定，例如画布与断点、网格和占比、字阶与行高、底色和对比、图片裁切或材质与光源。能引用现有 token 就用 token。新增数值带单位，注明设计起始值，可按设备和内容调整。
3. **填入能驱动视图的数据。** 表格、图表、地图和三维场景先确定对象 ID、显示字段、单位、时间及状态，再安排组件。列表、概览和详情引用同一批记录，汇总可以复算。无接口且需要预览时使用明确标记的演示样本，写明缺测与过期如何显示。展示型官网优先用已有文案和产品素材，业务指标应有来源。
4. **为关键操作写清前后状态。** 点名触发对象、输入方式、改变的属性、起止值、时长或进度、结束状态和降级方式。先判断用户需要看懂哪一个变化，再选择术语。静态页面也能完成任务时，可以只给选中、按压和焦点反馈。
5. **按交付物使用规格。** 生成静态效果图时写明画幅、目标状态与构图，多帧需求指明每帧差别。交互原型或前端实现将规格直接落实到样式、样本和事件。用户要提示词或设计交接时才单独输出规格。局部精修只写影响该区域的参数。

需要数值、业务样本或可直接交给渲染模型的写法时，读取[渲染参数与样例](references/render-spec.md)。需要命名、比较或实现具体效果时，按分类查[中英动效术语与选型](references/motion-vocabulary.md)。

## 按页面选择精修重点

| 页面与任务 | 第一版先确定 | 值得细化的交互 |
| --- | --- | --- |
| 官网、产品介绍、案例 | 首屏标题、主体图占比、图文顺序、主行动入口和窄屏裁切 | 首屏以下可用滚动显现或图文进度联动。每区默认至多一种装饰动效，正文与入口立即可见 |
| 控制台、表格、任务表单 | 筛选条件、列宽与单位、数值对齐、结果数、字段分组和主操作 | 筛选后保留上下文；错误就地说明修复方法；保存成功以实际结果为准，有撤销能力时提供入口 |
| 运营大屏、监控与图表 | 观察距离、主指标口径、时间窗、图例、更新时间、告警文本 | 选中异常后联动明细。实时报数立即展示最终值，局部短暂强调；缺测在图上断开并说明 |
| 地图、数字孪生与三维产品展示 | 场景主体、点位或部件 ID、图层、初始镜头、光照、标注遮挡和资产来源 | 列表与场景双向选中。拖动镜头与点选分开，关闭详情恢复原选择和视角。模型缺失时用清楚标记的示意图或列表 |
| 移动端、触屏作业 | 横竖屏布局、主操作热区、长标签换行、底部操作和内容安全区 | 悬停信息提供点按入口；拖拽提供可点选操作；返回恢复滚动位置、筛选和当前对象 |

## 实现与验收

- 先看静态首屏和关键状态，检查标题、主体、读数和下一步操作能否直接找到。覆盖实际涉及的加载、空结果、失败重试、部分缺测和过期状态。装饰层避免遮字、拦截输入或承担唯一状态提示。
- 微反馈可从 100–200 ms、弹层从 200–300 ms 起调。优先用现有组件及 CSS 的 transform、opacity；实时场景按目标设备衡量成本。频繁切换时取消旧动画和过期请求，最终画面与当前选择一致。
- 键盘可达，焦点可见。模态打开时将焦点转入并限制在其中，支持 Esc 关闭并归还焦点。主要操作支持触摸。开启 prefers-reduced-motion 时直接呈现终态，保留反馈、内容和业务流程。
- 有可运行页面时走一遍主要操作与返回路径，检查桌面、窄屏、键盘和减少动态效果；涉及触摸、实时数据或三维性能时说明验证设备与数据条件。静态图按指定帧检查构图和信息层级。交付时区分设计值、演示数据与实测结果。
